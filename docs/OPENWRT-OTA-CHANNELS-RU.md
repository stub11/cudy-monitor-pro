# Каналы обновлений Cudy Monitor Pro — OpenWrt

## Обычный канал (без изменения настроек)

- `sh /usr/share/cudy-monitor-pro/update-native.sh --check` — узнать доступную утверждённую версию.
- `sh /usr/share/cudy-monitor-pro/update-native.sh --apply` — штатное обновление с проверкой SHA-256, процесса и откатом.
- По умолчанию кандидатам GitHub `prerelease=true` и `draft=true` запрещено попадать в прямой поиск стабильных релизов.
- При недоступном API остаётся **только** вручную утверждённый список `packaging/openwrt/release-digests.txt` с SHA-256. Его нельзя автоматически наполнять тестовыми сборками.

**Исторический нюанс:** опубликованный OpenWrt `1.2.25` в GitHub отмечен как *Pre-release*, но уже внесён вручную в утверждённый список SHA-256. Этот исторический пакет сохраняется доступным через утверждённый список; его GitHub-метка сама по себе не означает прохождения полного аппаратного тестирования.

## Отдельный канал тестирования (явный выбор по SSH)

После выхода обновлённого скрипта на тестовое устройство:

1. `sh /usr/share/cudy-monitor-pro/update-native.sh --check-testing` — только проверка версий среди GitHub Pre-release (не изменяет пакет).
2. После резервного копирования и согласия владельца тестового устройства:
   `sh /usr/share/cudy-monitor-pro/update-native.sh --apply-testing --confirm-testing`.
3. Для тестирования выбираются только официальные GitHub-релизы OpenWrt с `prerelease=true`, `draft=false` и числовой версией `X.Y.Z` выше установленной. Разрешены только заранее предусмотренные URL проекта.
4. Тестовый пакет принимается **только** если официальный GitHub API предоставляет SHA-256 нужного APK. При HTTP 403, отсутствии метаданных или неправильной контрольной сумме операция прекращается, без перехода на утверждённый список обычного канала.
5. После установки проверяются установочный файл, реальный процесс, `/health`; неуспех приводит к предусмотренному откату. Для проверок можно запустить `--diagnose` (без обновления).

Тестовый канал не включается в веб-интерфейсе и не включается автоматически. Он не предназначен для основного домашнего роутера. Обычный `--check` и веб-панель не предлагают тестовые релизы, если те не были отдельно внесены в утверждённый список (чего делать нельзя).

**Важно:** команды `--check-testing` и `--apply-testing` начнут работать только после установки версии монитора, включающей данный код. Пока версия не опубликована, можно скачать артефакт сборки с опубликованной контрольной суммой SHA-256 GitHub Actions для ручной проверки на отдельном тестовом устройстве; действующий установщик `--file` намеренно принимает лишь пакет с закреплённым SHA-256 версии 1.2.25. Не обходить это ограничение без отдельного контролируемого протокола установки.

## Критерии проверки перед стабильным релизом

- [ ] Два последовательных тестовых номера сборок и опубликованные GitHub Pre-release.
- [ ] Ручной бэкап тестового роутера OpenWrt с согласия тестера.
- [ ] `--check` не выбирает новый тестовый релиз; `--check-testing` выбирает.
- [ ] `--apply-testing` без подтверждения не меняет ничего.
- [ ] Обновление на настоящем Cudy: версия файла, запущенного процесса и панели совпадает.
- [ ] Ошибка SHA-256 или недоступности API не запускает установку; при неуспешном обновлении проверен безопасный откат.
- [ ] Скриншоты сверены с оригинальным утверждённым `8237.png`, а не только с текстовым ТЗ.
- [ ] Все открытые Issues просмотрены и не содержат блокирующих замечаний.

Протокол не меняет DNS, маршруты, прошивку, firewall и сторонние службы.
