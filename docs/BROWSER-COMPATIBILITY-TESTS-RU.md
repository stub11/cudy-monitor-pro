# Совместимость браузеров — тестовый контур

Проверка добавлена после отзывов тестеров Netis N6 v2 об ошибках `same-origin confirmation required` и `origin mismatch`.

## Что теперь выполняет GitHub Actions

Workflow `.github/workflows/browser-compatibility.yml` запускает изолированный экземпляр отладочного Cudy Monitor Pro, а затем в реальных браузерных движках **Chromium** (основа Brave) и **WebKit** (основа Safari):

1. Открывает веб-панель, переключается на настройки.
2. Включает авторизацию через интерфейс и проверяет выдачу случайного ключа.
3. Проверяет, что без ключа монитор возвращает HTTP 401, а с ключом HTTP 200.
4. Эмулирует отсутствие заголовка `Origin` в запросах браузера.
5. Проверяет, что запрос установки обновления прошёл проверку происхождения. На тестовом сервере он ожидаемо возвращает HTTP 503, потому что системный установщик туда **не устанавливается**.
6. Отключает авторизацию и подтверждает восстановление доступа без ключа.

Тесты запускаются на GitHub Actions при изменении веб-интерфейса, сервера или самих браузерных тестов. Секреты пользователей и реальные устройства не задействованы.

## Что ещё нужно проверить на устройствах

| Устройство | Браузер | Проверка |
|---|---|---|
| Netis N6 v2 / OpenWrt 25.12.6 | Brave на Windows 10 | Авторизация и обновление через реальную панель |
| Netis N6 v2 / OpenWrt 25.12.6 | Safari на iOS | Авторизация и обновление через реальную панель |
| Cudy / Keenetic Ported + Entware | Браузер локальной сети | Проверка открытия, авторизации и штатного обновления IPK |

На реальном роутере перед установкой обновления подтвердить, что есть актуальная резервная копия. Проверять сначала кнопку «Проверить обновления», затем доступность релиза и только после этого запускать обновление. В случае ошибки записать версию панели, браузер, HTTP-статус, сообщение из вкладки «Обновления» и обезличенный журнал.

## Ограничения

WebKit на Linux не полностью совпадает с iOS Safari. Chromium на Linux не эквивалентен конкретной сборке Brave для Windows 10. Поэтому успешный CI — сильная регрессия кода, но **не подтверждение реальных устройств и установленного пакета**. Проверка отката нативного APK при сбоях всё ещё требует отдельного тестирования.

Автоматизированный тест: `tests/browser/browser-compat.js`. Workflow: `.github/workflows/browser-compatibility.yml`.
