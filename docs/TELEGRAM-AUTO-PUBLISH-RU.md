# Telegram: автоматические анонсы релизов (без ПК)

Автоматизация Cudy Monitor Pro использует только **GitHub Actions + Telegram Bot API**.
Домашний компьютер, Windows, Telegram Desktop и роутер не нужны для работы публикаций.

## Что делает

1. GitHub Actions собирает OpenWrt APK и Entware IPK после изменений в исходниках.
2. Облачный workflow `telegram-release-announcements.yml` проверяет релизы каждые 30 минут, а также поддерживает ручной запуск.
3. Скрипт публикует **один анонс на версию** только если оба файла:
   - `cudy-monitor-pro-X.Y.Z-r1.apk` в `cudy-monitor-openwrt-vX.Y.Z`;
   - `cudy-monitor-pro_X.Y.Z-1_aarch64-3.10.ipk` в `cudy-monitor-vX.Y.Z`
   уже загружены GitHub Releases, не являются черновиками и имеют SHA-256.
4. После подтверждения отправки создаёт тег `telegram-announced-vX.Y.Z`. Повторные запуски пропускают этот релиз.
5. При отсутствии второго пакета — ничего не отправляет, затем проверяет снова.

При отказе Telegram или отсутствующих правах на создание тегов job завершается ошибкой; повторный запуск допустим **после проверки отсутствия уже отправленного сообщения**, чтобы не создавать дубль.

## Один раз настроить бота

1. В Telegram откройте **@BotFather** и создайте отдельного бота через `/newbot`. Название и @username могут быть любыми свободными. Сохраните токен **только приватно**: это пароль к боту.
2. Добавьте бота в группу Z2K, в которой находится тема «Cudy Monitor Pro • CM Aurora», и разрешите ему публиковать сообщения в теме. Для этого достаточно минимальных прав на публикацию; удаление сообщений, управление участниками и добавление администраторов не нужно.
3. В приватном браузере откройте [GitHub Actions secrets](https://github.com/stub11/cudy-monitor-pro/settings/secrets/actions) и создайте **три Repository secrets**:
   - `CUDY_TELEGRAM_BOT_TOKEN`: токен из BotFather;
   - `CUDY_TELEGRAM_CHAT_ID`: публичный @username группы либо её numeric chat ID;
   - `CUDY_TELEGRAM_TOPIC_ID`: ID темы из ссылки на приглашение/тему. Важно: это **ID темы**, не ID обычного сообщения.
4. Зайдите в GitHub → **Actions** → **Announce verified Cudy Monitor release in Telegram** → **Run workflow**. Убедитесь, что сообщение появилось **в нужной теме**, а не в основном чате.
5. Все последующие обновления будут публиковаться автоматически после успешной сборки и появления обоих релизов. Никаких действий на ПК не требуется.

**Не присылайте токен в общую Telegram-тему, issue, README, скриншоты или сюда в открытом виде.** Он должен попасть непосредственно в GitHub Actions Secret.

## Статус подключения и контроль

Если секреты ещё не созданы, workflow завершится без отправки и запишет в Actions: `Telegram auto-publishing not configured`.

Скрипт находится в `scripts/telegram_release_publisher.py`; автоматические тесты — в `scripts/tests/test_telegram_release_publisher.py`. GitHub Actions никогда не публикует релизы, для которых отсутствует один из проверенных файлов.

При смене темы достаточно изменить `CUDY_TELEGRAM_TOPIC_ID` — перепубликовывать исходники не требуется.

Если бот скомпрометирован, отзовите токен у @BotFather и замените Repository secret. При смене команды/владельца проекта следует также пересмотреть права к репозиторию и группе.

## Принципы приватности

- В Telegram передаются только версия, публичные ссылки на GitHub и краткий текст CHANGELOG.
- IP-адреса роутеров, имена устройств, журналы, SSH, ключи и служебная телеметрия не собираются и не отправляются.
- CM Aurora остаётся отдельным приватным Android-проектом; его APK и исходники не публикуются этим workflow.
- Анонсы отправляются **без звукового уведомления** (`disable_notification`).
- Не устанавливайте на публичного бота права, не нужные для публикации.
