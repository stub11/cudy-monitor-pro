# Установка, доступ и удаление Cudy Monitor Pro

[← README](../README.md)

## Перед началом

Это **не прошивка**. Монитор работает как отдельная служба в Entware. Установка меняет файлы внутри `/opt` и перезапускает только собственную службу, но тестирование на чужих конфигурациях может обнаружить несовместимость.

Проверьте:
- ARM64: `uname -m` должен вывести `aarch64`.
- Entware: должны существовать `/opt/bin` и `/opt/etc/init.d`.
- USB или другой накопитель с `/opt` подключён и доступен для записи.
- Доступны `/opt/bin/curl`, `sha256sum`, `/bin/sh`.
- Создан резервный архив настроек вашего роутера и Entware.

Для KeeneticOS-подобной консоли после входа по SSH:

```sh
exec sh
```

Если уже отображается приглашение `/ #` или `~ #`, этот шаг не нужен.

## Установка из официального релиза

Скачайте установочный скрипт в Entware, **сначала прочитайте** его и только потом запускайте:

```sh
mkdir -p /opt/tmp
/opt/bin/curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/stub11/cudy-monitor-pro/main/cudy-monitor/scripts/install.sh \
  -o /opt/tmp/cudy-monitor-install.sh
sed -n '1,180p' /opt/tmp/cudy-monitor-install.sh
/bin/sh /opt/tmp/cudy-monitor-install.sh
```

Установщик берёт версию и SHA-256 бинарника из GitHub Release, сверяет скачанный файл и размещает его как `/opt/bin/cudy-monitor-pro`. Дополнительно устанавливаются `/opt/etc/init.d/S99cudy-monitor` и `/opt/share/cudy-monitor/update.sh`. Настройки в `/opt/etc/cudy-monitor` не должны стираться при повторной установке.

**Особенность BusyBox:** на некоторых роутерах `/bin/sh -n` не поддерживается. В актуальном установщике проверка в таком режиме не используется.

## Проверка локально

По умолчанию сервер слушает `127.0.0.1:8237` на самом роутере:

```sh
/opt/bin/cudy-monitor-pro --version
/opt/etc/init.d/S99cudy-monitor status
/opt/bin/curl -fsS http://127.0.0.1:8237/health
```

Последняя команда должна вывести `ok`. Служба не требует установленного D2K, DoQ или KeenKit.

## Доступ из локальной сети

**Внимание:** отдельной авторизации по паролю у панели нет. Разрешайте доступ только с устройств своей изолированной домашней сети.

Укажите **собственный LAN IPv4-адрес роутера** (ниже `192.168.1.1` — только пример; замените его на адрес вашего устройства):

```sh
printf '%s\n' '192.168.1.1:8237' > /opt/etc/cudy-monitor/bind
chmod 600 /opt/etc/cudy-monitor/bind
/opt/etc/init.d/S99cudy-monitor restart
```

После этого откройте `http://192.168.1.1:8237/` из браузера доверенного устройства. Убедитесь, что локальный firewall роутера разрешает соединения только из нужной LAN. **Не создавайте WAN port-forward и не открывайте гостям порт 8237.**

Чтобы вернуть прослушивание только на самом роутере:

```sh
printf '%s\n' '127.0.0.1:8237' > /opt/etc/cudy-monitor/bind
/opt/etc/init.d/S99cudy-monitor restart
```

## Обновления

Откройте в панели «Обновления» → «Проверить обновления», затем при необходимости выберите установку. Установщик OTA скачивает релиз с GitHub, проверяет SHA-256, сохраняет предыдущий бинарник и проверяет доступность HTTP `/health` после перезапуска.

Проверка через shell без установки:

```sh
/bin/sh /opt/share/cudy-monitor/update.sh --check
```

Откат к ранее сохранённому бинарнику (при его наличии):

```sh
/bin/sh /opt/share/cudy-monitor/update.sh --rollback
```

Обновление или откат может на короткое время прервать работу **самой панели**. Ни одно из этих действий не является гарантией отката системной конфигурации роутера.

Если установлена старая версия с недоступным источником релизов, см. [миграцию](../MIGRATION.md).

## Удаление

В Linux shell остановите монитор и удалите **только** принадлежащие ему исполняемый файл и init/OTA-скрипты:

```sh
/opt/etc/init.d/S99cudy-monitor stop
rm -f /opt/etc/init.d/S99cudy-monitor
rm -f /opt/bin/cudy-monitor-pro
rm -f /opt/share/cudy-monitor/update.sh
```

Это **не удаляет** конфигурацию `/opt/etc/cudy-monitor/`, резервный бинарник `/opt/bin/cudy-monitor-pro.previous` и старые резервные файлы OTA. Их можно убрать вручную после проверки, что они больше не нужны. Не удаляйте всю `/opt` или общие каталоги `init.d` / `bin`.

## Если что-то не работает

См. [решение типичных проблем](TROUBLESHOOTING.ru.md) и [безопасную отправку отчёта](TESTING.ru.md). Не публикуйте содержимое `/opt/etc` и реальные адреса домашней сети.
