# UI-инструменты и правила для Cudy Monitor Pro

Источник выбора: Griffin Wooldridge, "Stop Letting Claude Build Your Components From Scratch" (2026-11-07): https://www.youtube.com/watch?v=zsCGS-Yzjnw

## Архитектурный фильтр
Cudy Monitor Pro — малоресурсный Rust-сервер со встроенным HTML/CSS/JavaScript. Главный интерфейс работает без React, npm, CDN и внешних запросов в процессе работы. Утверждённый тёмный макет имеет приоритет над готовыми шаблонами.

**Не устанавливать** React, Tailwind, Vite или npm-зависимости прямо в роутер и не импортировать React-компоненты в `cudy-monitor/web/index.html`. Рассматривать React-стек лишь в отдельном проекте после одобрения смены архитектуры. В Cudy применять принципы качественных компонентов на нативных HTML/CSS/JS и проверять Chromium/WebKit.

## Каталог (выбирать по задаче)
- Основы: [shadcn/ui](https://ui.shadcn.com), [Base UI](https://base-ui.com), [Radix UI](https://www.radix-ui.com). Для Cudy — эталон семантики, фокуса, клавиатуры, контрастности, а не npm-инсталляция.
- Специалисты: [Sonner](https://sonner.emilkowal.ski) — уведомления; [Vaul](https://vaul.emilkowal.ski) — выдвижные панели; [cmdk](https://cmdk.paco.me) — команды; [NumberFlow](https://number-flow.barvian.me) — анимация чисел. Для Cudy использовать только необходимые UX-принципы. У часто обновляющихся показателей не анимировать каждый замер: это ухудшает читаемость и производительность.
- Визуальные примеры: [Beautiful UI](https://beautiful-ui.dev), [RareUI](https://rareui.in), [Magic UI](https://magicui.design), [Aceternity UI](https://ui.aceternity.com), [21st.dev](https://21st.dev). Не переносить тяжёлые эффекты и JavaScript-зависимости без аудита лицензий, размеров и надёжности.
- Навык подбора: `.agents/skills/pick-ui-library/SKILL.md`, исходник https://github.com/emilkowalski/skills (MIT; лицензия рядом). Навык вызывается явно, когда требуется выбрать новый компонент.

## Реальные решения для Cudy
1. Селекты и поля журналов: осмысленные названия платформ, доступные состояния `ошибка / пусто / данные`, читаемый фокус и отсутствие переполнения на 360–390 px.
2. Показатели CPU/RAM/WAN: сохранить ширину карточки и высоту строк при обновлении, не заменять `нет данных` выдуманным `0`.
3. Сообщения об ошибках: короткие, объясняющие, не закрывающие графики; никакого позитивного статуса при 401 или ошибке API.
4. Для подтверждения опасных действий: явное согласие, проверка результата на сервере; не копировать бездумно визуал системных уведомлений.
5. Не менять внешний вид приложения без сравнения с утверждёнными макетами.

## Контроль качества
- Профили: узкий Android 360–390 px, десктоп 1366 px; Chromium + WebKit.
- Проверять длинные значения, пустой результат, сетевую ошибку, 401, смену вкладок и возврат после повторного подключения.
- Не вводить внешние CDN, телеметрию, секреты или дополнительные фоновые службы.
- Исходники и CI — в GitHub; локальные файлы и кэши проекта на ПК допускаются только в `D:\AI` и `U:\AI work`.
