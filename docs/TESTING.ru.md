# Как протестировать Cudy Monitor Pro и сообщить об ошибке

[← README](../README.md) · [Установка](INSTALL.ru.md) · [Создать баг-репорт](https://github.com/stub11/cudy-monitor-pro/issues/new/choose)

Спасибо за тестирование. Проект предназначен прежде всего для **ARM64-роутеров с Entware** и пока находится на стадии публичного тестирования.

## Безопасный минимальный сценарий

1. Сделайте резервную копию конфигурации роутера и Entware до установки.
2. Проверьте `uname -m` — ожидается `aarch64`. Запишите модель и прошивку без серийного номера.
3. Установите монитор по [инструкции](INSTALL.ru.md) с сервера GitHub Releases.
4. Проверьте `/health`, главную страницу и системную нагрузку.
5. Сравните загрузку CPU, память, температурные датчики и свободное место с данными, которые показывает сам роутер.
6. Проверьте сетевые графики на телефоне и ПК, ориентацию экрана и изменение масштабирования.
7. Убедитесь, что исчезновение необязательной службы не мешает самой панели.
8. Проверьте повторный запуск **самого монитора**. Перезагружать роутер только ради теста не требуется.
9. Проверьте наличие новой версии кнопкой «Проверить обновления», **не устанавливая неподтверждённую сборку**.

Не проверяйте кнопки остановки D2K/DoQ на рабочем домашнем интернете без отдельной подготовки: можно временно потерять доступ к сайтам.

## Что указать в Issue

- Версия Cudy Monitor Pro и ссылка на релиз.
- Модель роутера (без серийного номера) и версия прошивки.
- Архитектура (`aarch64`) и наличие Entware.
- Браузер/операционная система и тип экрана.
- Что ожидалось и что произошло на самом деле.
- Чёткие шаги воспроизведения.
- Есть ли проблема после перезапуска **монитора**.
- Можно ли воспроизвести без D2K/DoQ.
- Обезличенный скриншот, если он помогает.

## Чего нельзя публиковать

Не прикладывайте сырые `/api/status`, `/api/logs`, журнал роутера, дампы конфигурации и архивы бэкапов: они могут содержать имена процессов, локальные адреса и другую информацию.

Перед публикацией удалите:
- публичный и частный IP, IPv6, MAC, SSID, имена устройств и hostname;
- ключи, токены, cookies, SSH-логины/пароли, URL с секретами;
- реальные имена, почты, сообщения, уникальные идентификаторы устройств;
- геолокационные сведения и сетевую топологию, если не хотите их раскрывать.

Замените чувствительные значения на `[REDACTED]`. Если проблему нельзя описать без секрета, **не создавайте публичный Issue с этим секретом**; используйте приватное сообщение о безопасности, если соответствующий канал включён.

## Полезные результаты теста

| Область | Что проверить |
|---|---|
| Ресурсы | CPU и RAM, при отсутствии датчика корректный пустой статус |
| Сеть | Положительные значения, правильные единицы скорости, отсутствие искажений подписей |
| Хранилище | Монтирование `/opt`, отображение свободного/занятого места |
| UI | Телефон/ПК, длинные названия, горизонтальная прокрутка только там, где нужна |
| Обновление | Неверный SHA или отсутствие сети не должны оставлять нерабочую установку |
| Безопасность | С панели нельзя управлять сервисами по умолчанию |

Пожалуйста, сообщайте и об успешных тестах: модель и версия прошивки помогут понять, какие устройства реально совместимы.
