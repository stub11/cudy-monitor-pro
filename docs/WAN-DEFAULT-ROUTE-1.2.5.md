# Активный WAN по основному маршруту IPv4 (версия 1.2.5)

Источник подхода: CM Aurora (`V0_1_116_HOME_WAN_PRESENTATION.md` и проверки сетевых счётчиков). Реализация самостоятельная, в Rust + JavaScript. Исходный код и приватные данные CM не публикуются.

- Backend парсит `/proc/net/route` и выбирает default route (`Destination=00000000`, `Mask=00000000`, `RTF_UP`), предпочитая минимальное значение Metric. Работают нестандартные имена (`pppoe-wan`, `eth2.4`, `wan0` и т.д.). Маршруты с одинаковым приоритетом на нескольких разных интерфейсах трактуются как неоднозначные, автоматического выбора нет.
- Новые необязательные поля JSON status: `wan_iface` (имя интерфейса или `null`), `wan_route_status` (`main_ipv4_route`, `ambiguous`, `missing`). Старые поля API сохраняются.
- По умолчанию UI использует интерфейс из таблицы маршрутов только если он найден в актуальном списке интерфейсов `/proc/net/dev`; при смене маршрута перепривязывает историю и не смешивает линии разных WAN. Ручной выбор сохраняется, пока выбранный интерфейс существует.
- При нескольких одинаковых приоритетах интерфейс выбирается пользователем вручную; показания выбранного интерфейса не считаются подтверждённым активным WAN.
- Таблица маршрутизации может учитывать только main table. Это НЕ проверка интернета, резервного провайдера или policy routing / PBR. Нельзя утверждать, что маршрутизатор имеет работающий интернет только на основании default route.
- Отдельные VLAN, PPP и bridge счётчики не складываются в суммарную скорость — это исключает двойной подсчёт.
- Не меняются маршруты, DNS, WAN, firewall или другие службы. Это только чтение статистики.

Проверки: unit-тесты основного маршрута, метрик, равных приоритетов, отсутствующего default route и небезопасных имён; CI Rust/API, JavaScript-синтаксис, мобильный UI. Реальный много-WAN/PBR тест требует отдельного испытания.

Проект CM Aurora остаётся нетронутым. Пользовательские пути: D:\AI и U:\AI work.
