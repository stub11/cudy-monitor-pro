# Cudy Monitor Pro

**Лёгкая веб-панель мониторинга роутеров ARM64 на Rust.** Работает локально, без регистрации, внешних CDN и обязательной телеметрии. Интерфейс открывается с телефона или ПК через браузер.

## Быстрый старт: всё в одном месте

**Поддерживаемые варианты:** OpenWrt 25.12+ на ARM64 с нативным пакетным менеджером `apk`, либо Keenetic Ported на ARM64 с установленным и смонтированным в `/opt` Entware. Установщик сам определяет тип системы и выбирает нужный вариант. Наличие Entware на OpenWrt для нативного APK не требуется.

1. Подключитесь к роутеру по SSH под `root` (PuTTY, Termius или другой SSH-клиент).
2. Если на Keenetic Ported видно приглашение `(config)>`, один раз выполните `exec sh` для входа в Linux shell. На OpenWrt этот шаг не требуется.
3. Скопируйте **одну нужную команду целиком** и вставьте в SSH.

### 1. Установка — одна команда

```sh
wget -qO /tmp/cudy-monitor-easy.sh https://raw.githubusercontent.com/stub11/cudy-monitor-pro/main/scripts/easy-install.sh && /bin/sh /tmp/cudy-monitor-easy.sh --install
```

Установщик проверит платформу и ARM64, скачает нужные файлы, проверит контрольную сумму выпускаемого пакета/бинарника, установит и запустит монитор. При обнаружении единственного подходящего локального IP панель активируется для домашней LAN. Настройки DNS, Wi-Fi, маршрутизации и firewall не меняются.

**После установки:** в SSH появится адрес панели вида `http://192.168.1.1:8237/`. Это **пример** — используйте адрес, который вывел установщик. Откройте его в браузере телефона или ПК, подключённого к **домашней Wi-Fi/LAN этого роутера**. Не вводите ссылку в SSH и не пытайтесь открыть APK как Android-приложение.

Если панель не открывается, проверьте подключение телефона к основной, а не гостевой сети и следуйте разделу «Если не открывается» ниже.

### 2. Обновление — одна команда

```sh
wget -qO /tmp/cudy-monitor-easy.sh https://raw.githubusercontent.com/stub11/cudy-monitor-pro/main/scripts/easy-install.sh && /bin/sh /tmp/cudy-monitor-easy.sh --update
```

Для **нативного OpenWrt APK** скрипт скачивает и устанавливает актуальный выпуск, сохраняет настройки. Для **отдельной установки Entware** он обновляет бинарник со штатными проверками и восстановлением при неудаче.

**Исключение:** если монитор ранее установлен как управляемый пакет **Entware IPK через opkg**, скрипт не смешивает этот режим с обычной установкой и сообщит об этом. Обновляйте такой пакет через Entware `opkg` либо используйте документированную миграцию.

### 3. Удаление — одна команда

```sh
wget -qO /tmp/cudy-monitor-easy.sh https://raw.githubusercontent.com/stub11/cudy-monitor-pro/main/scripts/easy-install.sh && /bin/sh /tmp/cudy-monitor-easy.sh --remove
```

Удаляется **только Cudy Monitor Pro**. Нативный OpenWrt-пакет удаляется через `apk`, зарегистрированный Entware IPK — через `opkg`, отдельно установленный Entware-монитор — удалением его известных файлов. Остальные службы и Entware остаются. **Настройки монитора сохраняются**, чтобы при необходимости его можно было установить снова.

### Если LAN определяется неоднозначно

Монитор не выбирает случайный адрес, если на роутере несколько локальных интерфейсов. Узнайте его LAN-IP через `ip -4 addr show`. Для **OpenWrt с нативным APK** укажите реальный IP, например:

```sh
cudy-monitor-lan --bind-ip 192.168.1.1
```

Для **Keenetic Ported с отдельной установкой Entware** используйте установщик с `--bind-ip`, как описано в [дополнительной инструкции](docs/INSTALL.ru.md). `192.168.1.1` — только пример: команда не изменяет адрес роутера.

### Если панель не открывается

- Проверьте, что вы открываете `http://IP-роутера:8237/` на устройстве в доверенной домашней сети.
- OpenWrt: `/etc/init.d/cudy-monitor-pro status` и `cat /etc/cudy-monitor-pro/bind`.
- Keenetic Ported/Entware: `/opt/etc/init.d/S99cudy-monitor status` и `cat /opt/etc/cudy-monitor/bind`.
- При ошибке скачивания GitHub проверьте работу `wget`/DNS/HTTPS. Не нужно перепрошивать роутер или менять DNS ради монитора.
- Если остались вопросы, создайте [Issue](https://github.com/stub11/cudy-monitor-pro/issues) с моделью, версией прошивки, текстом ошибки и скриншотом **без паролей, токенов и внешнего IP**.

Исходник единого установщика доступен для просмотра перед запуском: [scripts/easy-install.sh](scripts/easy-install.sh). Установка предполагает доступ роутера к GitHub; если `wget` отсутствует, скачайте скрипт другим доступным средством. Нативный OpenWrt APK — экспериментальный пакет, который устанавливается с `--allow-untrusted` после проверки SHA-256, а не через доверенный подписанный репозиторий.

### Если GitHub Releases недоступен с роутера

Сообщение `ERROR: Cannot download APK from GitHub` означает ошибку **скачивания**, а не несовместимость маршрутизатора. В обновлённом установщике есть попытка через `curl` после `wget`, а также поддержка установки уже скачанного файла.

Если скачивание не получилось, загрузите APK на телефон/ПК и передайте на роутер в `/tmp/cudy-monitor-pro-1.2.7-r1.apk` через SFTP/SCP. Затем выполните:

```sh
wget -qO /tmp/cudy-monitor-easy.sh https://raw.githubusercontent.com/stub11/cudy-monitor-pro/main/scripts/easy-install.sh && sh /tmp/cudy-monitor-easy.sh --install --file /tmp/cudy-monitor-pro-1.2.7-r1.apk
```

Контрольная сумма SHA-256 проверяется перед установкой. [Подробное решение проблемы загрузки](packaging/openwrt/INSTALL-TESTER-RU.md#если-скачивание-apk-с-github-не-работает).

### Обновление из панели на OpenWrt

**С версии 1.2.8** нативный OpenWrt APK поддерживает проверку и установку обновлений прямо из вкладки «Обновления». Устанавливается только официальный релиз Cudy Monitor Pro с проверкой SHA-256, резервной копией предыдущего APK и попыткой отката при ошибке. Для версий до 1.2.8 обновитесь один раз по SSH через единую команду `--update` из раздела «Быстрый старт».

**Авторизация:** по умолчанию выключена. В разделе «Настройки → Авторизация панели» можно включить защиту случайным ключом доступа, сохранить ключ и позднее отключить защиту. Если ключ потерян, восстановление через SSH описано в [инструкции по авторизации](docs/AUTH-AND-NATIVE-OTA-1.2.8.md). **Внимание:** при выключенной авторизации любой клиент доверенной домашней LAN способен инициировать обновление; HTTP не шифрует ключ. Не открывайте порт 8237 в интернет или гостевые сети.

## Возможности

- CPU: нагрузка, ядра и частота (когда данные доступны).
- RAM, процессы, температура, накопители/Entware и аптайм.
- Сетевые интерфейсы и графики скорости. Активный WAN в версии 1.2.5 определяется по основному маршруту IPv4, а не по названию интерфейса; поддерживаются PPPoE и VLAN. При неоднозначных маршрутах доступен ручной выбор. После ручного выбора кнопка «Автоматический WAN» возвращает график к интерфейсу основного маршрута IPv4. Это не тест доступности интернета или policy routing.
- История ресурсов в RAM до 3 часов; история сети до 5 минут. После перезапуска история сбрасывается.
- Обнаружение установленных D2K, DoQ, KeenKit, если они есть.
- Локальный веб-интерфейс с мобильной адаптацией и отдельными страницами мониторинга.

Монитор **не устанавливает** D2K, DoQ, KeenKit, не изменяет прошивку и не подменяет системные показатели демонстрационными значениями. Отображение датчиков и служб зависит от возможностей роутера.

## Совместимость

| Система | Условия | Состояние |
|---|---|---|
| Keenetic Ported / KeeneticOS | ARM64, смонтированное Entware в `/opt` | Проверено на Cudy WBR3000UAX; версия 5.1.8 требует отдельной проверки |
| OpenWrt 25.12+ | ARM64, нативный `apk` | Нативный пакет; тест на Netis N6 v2 прошёл, другие модели требуют проверки |
| Другие Linux/прошивки | MIPS, ARMv7, системы без нужного пакетного менеджера | Не заявлены как совместимые |

**Не устанавливайте одновременно нативную OpenWrt APK-версию и Entware-вариант**: они используют один порт 8237. Наш установщик обнаруживает такой конфликт и прекращает установку.

## Безопасность и приватность

**У веб-панели нет пароля.** Открывайте её только в доверенной домашней LAN. **Не пробрасывайте порт TCP 8237 в интернет**, гостевую Wi-Fi-сеть или общедоступный туннель. Управление системными службами отключено по умолчанию.

Монитор работает локально; браузер обращается к роутеру напрямую. Данные графиков и событий находятся в оперативной памяти, а проверка новых версий обращается к GitHub Releases. Подробнее: [Приватность](docs/PRIVACY.ru.md) · [Безопасность](SECURITY.md).
