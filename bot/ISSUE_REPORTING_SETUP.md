## 1. Создать отдельный GitHub Fine-grained Personal Access Token

Создайте его в настройках GitHub: https://github.com/settings/personal-access-tokens/new

- Resource owner: `stub11`
- Repository access: **Only select repositories** → только `cudy-monitor-pro`
- Repository permissions: **Issues — Read and write**; остальные разрешения оставить только обязательными по умолчанию (Metadata — Read)
- Expiration: ограниченный срок, например 90 дней; по истечении заменить токен без изменения кода
- Название: `cudyapp-issues-only`

Никогда **не присылайте токен в Telegram, ChatGPT, публичный GitHub, скриншоты или Issue**. Если GitHub требует дополнительного согласования прав, сначала завершите его. Не используйте классический PAT с доступом ко всем репозиториям.

## 2. Сохранить токен только в Vercel Production

Откройте Vercel → `cudyapp-community-bot` → Settings → Environment Variables:

- Key: `CUDY_GITHUB_ISSUE_TOKEN`
- Value: скопированный GitHub fine-grained token
- Environment: только **Production**
- Type: **Sensitive** (если доступно)
- После сохранения не раскрывайте значение в истории чата и на скриншотах

## 3. Проверить до включения

- Проверить, что присутствуют **имена** обеих переменных, не считывая их секретные значения.
- Проверить, что GitHub-токен действительно ограничен Issues одного репозитория.
- Проверить свежий Production deploy Vercel и ошибки приложения.
- Убедиться, что `CUDY_ISSUE_REPORTS_ENABLED` пока `false`; автоматические публикации не идут.
- Затем заменить **только** `CUDY_ISSUE_REPORTS_ENABLED` на `true` в Production и создать новое Production-развёртывание для получения новых переменных.

## 4. Пробная публикация

В теме `87621` отправьте `/cudy_problem`, нажмите на кнопки: система, категория, выполненная проверка. Прочитайте предварительное описание и явно нажмите **«Опубликовать только обезличенный отчёт»**.

После этого появится Issue, содержащий исключительно одну из трёх разрешённых категориальных меток: систему, симптом и выполненную проверку. Заголовок и текст строятся только из заранее проверенных значений. Имена, Telegram ID, сообщения, пароли, локальные/внешние IP, токены и логи не передаются.

Текущая схема объединяет одинаковые успешно созданные отчёты в течение 24 часов; неудачную отправку можно повторить. Успешный Issue публикуется без дополнительного уведомления в общий чат, но только после явного согласия.

## Откат

В Vercel немедленно установить `CUDY_ISSUE_REPORTS_ENABLED=false`, выполнить новое Production-развёртывание и при необходимости **отозвать** fine-grained токен в GitHub. Для выключения не нужно менять Telegram webhook, Redis, релизы или остальные проекты.

**Ограничение:** GitHub Issues — публичный ресурс. Именно поэтому бот не передаёт свободный текст участников и никогда не создаёт Issue без их согласия. Нет скрытой автоматической отправки данных из переписки.
