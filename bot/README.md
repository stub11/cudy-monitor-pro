## Права и веб-хук

@Cudyapp должен быть администратором группы с правом удаления сообщений. Другие административные права не нужны. Проверьте, что он получает обычные сообщения группы, а не только команды.
После добавления токена и Redis в Vercel задайте Telegram webhook на https://<vercel-domain>/api/webhook.
Webhook требует специальный заголовок X-Telegram-Bot-Api-Secret-Token; секрет — SHA-256 от bot token и строки |cudyapp-topic-webhook-v1.
Никогда не публикуйте токен в README, issue, логах или чате.
Не подключайте веб-хук до установки токена на Vercel: Telegram будет отправлять все входящие сообщения на новый адрес.

## Диагностика обращений и обезличенные GitHub Issues

Бот обнаруживает сообщения вроде «панель не открывается» или принимает команду `/cudy_problem` **только в теме CM Aurora**. Сначала задаёт три коротких уточнения через команды:

1. `/cudy_platform openwrt|keenetic|other` — система роутера.
2. `/cudy_symptom install|panel|update|network|other` — категория проблемы.
3. `/cudy_tried docs|restart|nothing|other` — что уже проверялось.

Затем бот показывает сведения из публичного README и предлагает `/cudy_report`, если проблема осталась. **Только это действие означает согласие на публикацию обезличенного отчёта в публичном GitHub Issues.** Сама переписка, сырые логи, фотографии, ID пользователей, IP, токены и пароли **не публикуются**. Пользователю заранее сообщается, что именно будет отправлено. Команда `/cudy_cancel` прекращает опрос без публикации.

Для экономии запросов бота однотипные отчёты объединяются по хешу на 24 часа. Данные опроса хранятся в Redis ограниченное время (30 минут). Бот не опрашивает участников из других тем и не открывает SSH/локальные файлы. Если не хватает данных или пользователь отказался, GitHub Issue не создаётся.

**Автоматическое создание Issue первоначально выключено.** Для дальнейшего включения владелец должен добавить в Vercel Production отдельный минимально привилегированный GitHub токен `CUDY_GITHUB_ISSUE_TOKEN` с доступом только к Issues одного репозитория и установить `CUDY_ISSUE_REPORTS_ENABLED=true`. Не использовать Telegram-токен или универсальный GitHub PAT. Ничего секретного не хранить в публичном репозитории.

Технические отчёты в случае согласия отправляются **без дополнительного анонса в общий чат**, но пользователь заранее информирован о публикации. Это сохраняет приватность и исключает тайное копирование содержания чужих сообщений.

При ошибке GitHub отчёт не публикуется, а бот предлагает официальную ссылку на Issues. Публикация релизов и управление роутером не затрагиваются.

Доступные шаблоны: `bot/lib/problem-intake.js`; тесты: `bot/tests/problem-intake.test.js`.

## Удобная диагностика через Telegram inline-кнопки

Новый режим не требует ручного ввода команд после `/cudy_problem`: бот предлагает кнопки платформы (OpenWrt / Keenetic Ported / другая), типа неисправности и выполненной проверки. Кнопки содержат только короткие фиксированные значения, а не тексты участников.

- Бот обрабатывает `callback_query` исключительно в супергруппе и теме CM Aurora; нажатие кнопки пользователем без активного собственного опроса не запускает чужой опрос.
- Сессия хранится в Redis отдельно по теме и идентификатору участника, 30 минут. Сообщения, пароли, IP, логи и Telegram ID в GitHub Issues не попадают.
- После трёх шагов появляются кнопки «Опубликовать только обезличенный отчёт» и «Отмена». Без согласия ничего не отправляется. **Отправка Issue выключена до отдельной настройки минимально привилегированного токена и флага.**
- При повторном нажатии на устаревшую кнопку бот показывает короткий ответ, а не начинает новый опрос для другого человека.
- При обновлении регистрации Telegram webhook необходимо включить `callback_query` в `allowed_updates`. Скрипт `bot/scripts/register_webhook.py` обновлён и не сбрасывает ожидающие Telegram-сообщения (`drop_pending_updates=false`).
- До повторной регистрации webhook новые inline-кнопки будут показываться, но нажатия на них не будут доставляться в бот. Команды с текстом работают по-прежнему.
