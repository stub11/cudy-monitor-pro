# Cudyapp — реакции, стикеры и модерация темы Z2K

Используется существующий @Cudyapp. Публикация релизов из GitHub Actions остаётся без изменений.

## Функции

- Реакции на слова: текст, эмодзи, Telegram sticker_file_id, фото по HTTPS и GIF-анимации по HTTPS. Триггеры пока пусты.
- Модерация: удаление очевидного мата и прямых оскорблений, предупреждения с ограничением частоты.
- Антифлуд: больше 6 сообщений за 20 секунд в одной теме, без автоматического бана или мута.
- Обработка ТОЛЬКО темы 87621 группы @zapret2keenetic.
- Ограничение реакций: не чаще одного ответа за 40 секунд в теме.

## Настройка триггеров

Отредактируйте bot/config.json, reactions.triggers. Пример элемента массива:

    {
      "words": ["привет", "куку"],
      "responses": [
        {"text": "Привет! 🦊"},
        {"sticker_file_id": "FILE_ID_СТИКЕРА"},
        {"photo_url": "https://example.org/image.png", "text": "Класс!"},
        {"animation_url": "https://example.org/animation.gif", "text": "Ура! 🎉"}
      ]
    }

Это только пример, по умолчанию ни один триггер не активирован. Используйте изображения, на публикацию которых есть право. Для стикеров требуется Telegram file_id.

## Облачное размещение

Исходники: bot/api/webhook.js. Проект Vercel привязывается к GitHub stub11/cudy-monitor-pro с rootDirectory=bot.
Существующий GitHub Actions Secret нельзя прочитать или скопировать автоматически в Vercel.
В Vercel задаются переменные окружения:

- CUDY_TELEGRAM_BOT_TOKEN — прежний токен @Cudyapp, как Sensitive/Encrypted.
- CUDY_TELEGRAM_CHAT_ID — @zapret2keenetic.
- CUDY_TELEGRAM_TOPIC_ID — 87621.
- UPSTASH_REDIS_REST_URL и UPSTASH_REDIS_REST_TOKEN — приватное Redis REST-хранилище.

ВАЖНО: Пока Redis не подключён, антифлуд, подавление повторов и реакции отключены, чтобы не допускать ошибочную модерацию на нескольких экземплярах Vercel. При этом удаление сообщений с явным матом/оскорблениями может работать без Redis, если Telegram webhook активен.

## Права и веб-хук

@Cudyapp должен быть администратором группы с правом удаления сообщений. Другие административные права не нужны. Проверьте, что он получает обычные сообщения группы, а не только команды.
После добавления токена и Redis в Vercel задайте Telegram webhook на https://<vercel-domain>/api/webhook.
Webhook требует специальный заголовок X-Telegram-Bot-Api-Secret-Token; секрет — SHA-256 от bot token и строки |cudyapp-topic-webhook-v1.
Никогда не публикуйте токен в README, issue, логах или чате.
Не подключайте веб-хук до установки токена на Vercel: Telegram будет отправлять все входящие сообщения на новый адрес.

## Статус развёртывания 10.11.2026

Создан отдельный облачный проект Vercel `cudyapp-community-bot`, адрес `https://cudyapp-community-bot.vercel.app/api/webhook`. Первая production-сборка находится в состоянии READY. Проект развёрнут из исходных файлов без связки Vercel↔GitHub, поскольку Vercel запросил дополнительное GitHub Login Connection. Код при изменениях на GitHub не обновляется на Vercel автоматически — требуется новая публикация.

В Vercel уже установлены `CUDY_TELEGRAM_CHAT_ID=@zapret2keenetic` и `CUDY_TELEGRAM_TOPIC_ID=87621`. **Отсутствует только секрет `CUDY_TELEGRAM_BOT_TOKEN`**. Ранее сохранённый GitHub Actions Secret нельзя прочитать и перенести между приложениями. Не публикуйте токен в чате или исходниках.

После того как владелец проекта добавит тот же токен @Cudyapp в Vercel → Project → Settings → Environment Variables как **Sensitive** для Production, потребуется новый production deploy. После проверки доступности приложения запустите GitHub Actions → `Activate Cudyapp Telegram webhook` → `Run workflow`. URL уже указан в workflow, повторно вводить его не требуется. До завершения этих шагов webhook **не подключён**, а публикация релизов GitHub Actions работает как прежде.

Для устойчивого антифлуда и реакций нужен Upstash Redis (`UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN`). До подключения Redis эти две функции не действуют. Модерация очевидного мата и адресных оскорблений может работать отдельно, когда настроен токен и webhook и у бота есть право удаления сообщений.

## Подключение через GitHub Actions

Telegram webhook регистрируется только вручную, после успешного развёртывания и настройки секрета. Скрипт `bot/scripts/register_webhook.py` использует существующий GitHub Actions Secret и отправляет запрос к Telegram по HTTPS, не печатая токен. Откройте `.github/workflows/cudyapp-activate-webhook.yml` и запустите вручную. Секретный заголовок защищает webhook от посторонних вызовов.

Важно: **не пересылайте токен Rose Cloner или другим сторонним ботам.** Мы используем только @Cudyapp, GitHub и собственное Vercel-размещение.

## Приватность и безопасность

Тексты сообщений не сохраняются. Redis содержит только кратковременные счётчики с TTL. При сбое хранилища бот не наказывает за флуд. Автоматические баны и муты выключены.
Регулярные выражения могут ошибаться: проверяйте качество модерации по отзывам пользователей.

Для анимированных GIF используйте `animation_url` со ссылкой HTTPS, доступной серверам Telegram. Бот отправляет её через `sendAnimation`.
